# SwitchEnv 开发指南

SwitchEnv 是一个原生 Windows 环境变量管理器，使用 C# 和 WPF，实现左侧配置组切换、右侧变量表格、单个/批量变量移动和独立的 PATH 列表编辑器。采用 MIT 许可证，运行时不依赖第三方包。

## 构建

在 Windows PowerShell 中进入本目录，执行：

```powershell
.\build.ps1
```

构建产物位于 `build\SwitchEnv.exe`，同时生成所需的 `.config` 文件。也可以指定目录：

```powershell
.\build.ps1 -OutputDirectory '.\dist'
```

要求 Windows 10 / 11、.NET Framework 4.8 或更新版本。脚本调用 Windows 自带的 .NET Framework C# 编译器，优先使用 64 位框架目录，无需下载依赖或安装 .NET SDK。语言版本为 C# 5，目标为 AnyCPU。

如果 PowerShell 的脚本执行策略阻止运行，可对当前构建进程使用：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

## 测试

```powershell
.\test.ps1
```

测试程序及输出位于 `test-results`，可通过 `-TestDirectory` 指定其他目录。

测试包含内存环境、JSON 持久化、注册表原始字符串读写、旧自启迁移以及 Windows 任务计划程序的原生 XML 解析。注册表测试只写入 `HKCU\Software\SwitchEnv.Tests\<随机 ID>` 并清理该测试项。任务的开启和关闭使用内存实现。原生验证会创建内存中的任务定义。测试前后比较现有用户与系统环境、自启注册表项和本账号 SwitchEnv 任务。执行环境需要允许写入这个临时注册表项，并能连接本机任务计划程序服务。结果见[验证记录](verification.md)。

## 运行与数据

正常运行：`SwitchEnv.exe`，默认通过 ShellExecute `runas` 请求管理员权限；取消 Windows 权限提示后直接退出，在读取数据、创建主窗口和修改设置之前完成提权。体验模拟环境：`SwitchEnv.exe --demo`，无需提权。

左下角“开机自启”开关创建 `SwitchEnv.Startup.<当前用户 SID>` 任务。任务绑定当前账号的登录触发器，使用 `InteractiveToken` 和 `HighestAvailable`，登录五秒后以管理员权限执行 `--startup` 并驻留托盘。不保存密码，电池供电时允许运行，无执行时长上限。注册时要求程序已经提权；管理员与 SYSTEM 可管理任务，当前账号可读取。关闭开关只删除与当前程序和数据目录匹配的任务。参考 [微软任务安全上下文文档](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks)。

设置默认关闭。如果原路径已有 0.1.1/0.1.2 的 Run 自启项，正常启动后先创建最高权限任务，成功后清理匹配的旧项；任务创建失败会保留旧项。移动程序后请重新开启自启；从旧版的不同路径升级，应先在旧版关闭自启。任务单独保存程序路径、工作目录和参数，自定义数据目录写入 `--data-dir`，默认相邻的 `data` 不重复加入命令。路径带空格、Unicode 和盘符根目录经过 Windows 参数解析验证。

提权和自启都携带当前用户 SID；提权后账号发生变化会在读写数据之前拒绝启动，避免使用另一账号的 HKCU。正常运行要求当前账号具有管理员资格。manifest 保持 `asInvoker`，由启动逻辑请求权限，让演示和截图模式可以使用普通权限；这两种模式禁用自启设置。

真实数据保存在程序旁的 `data`，演示数据保存在 `demo-data`。可使用 `--data-dir "目录"` 指定数据位置。正常启动和编辑配置组不会自动写入环境变量；实际写入需要确认修改预览。用户操作说明见 `使用说明.md`。

多个配置组可以同时启用。`State.ActiveGroups` 按从低到高的优先级保存启用记录；每组保存最后一次应用的 `Entries`、逐层输入 `Original` 和逐层输出 `Applied`。配置组定义中的待应用编辑与这些快照分开保存。主界面使用 `GroupPlanner`；原有单组 `Planner.Switch` 适配器保留用于回归测试。

计算时以同一变量最早的 `Original` 恢复真实基准，再依次执行已应用的组定义。设置/删除覆盖较低优先级的结果；前置/追加依次合并并去重。更新保留当前顺序，菜单可提高组优先级。停用任意组只移除该层并重算相关键，最后一个管理者退出后恢复真实基准。用户/系统范围分别计算。

外部修改检查针对受影响键的最终输出，避免把被高优先组覆盖的低层输出当成外部修改。执行前检查整套启用状态及变量快照；提交前再次检查包括值未变化的受影响键。事务及历史保存完整组集合和顺序，移动、异常恢复及撤销沿用原有日志和回滚流程。

注册表值使用原始字符串读取，不展开 `%VAR%`，不调用 `setx`。写入前保存事务记录，检查外部修改，失败时回滚；后续进程通过系统环境块获取新的环境。

变量移动通过同一个 `Plan` 同时描述本机修改和 `ProfileEntryChange`。执行前检查配置组定义和注册表值；原始状态先写入恢复记录，本机写入成功后原子保存完整状态。失败时回滚本机写入，配置组仍保留原内容。历史记录保存配置组定义的前后值，恢复最近一次移动时同步还原相关定义和管理状态。旧历史没有 `ProfileChanges` 字段时仍可读取和恢复。

移动已启用配置组的变量只调整相关定义，其他变量及未应用的编辑继续保留。移动后从真实基准重新计算受影响键的全部管理者；移入已启用目标时保留原有真实恢复基准，新接收的变量以来源移除后的本机状态为基准。移到本机的变量不再由来源组恢复；同范围还有其他管理者时会阻止直接移到本机。

`MoveBatch` 先检查重复来源、同一目标冲突和来源/目标相互覆盖，在副本上规划全部移动；将修改合并为一个 `Plan` 后才执行。所有环境前置条件都引用最初的快照，配置组修改保存初值和最终值，整批使用一次日志、一次状态提交及一条历史记录。规划中的错误不会修改传入状态；执行失败会尝试回滚已写入值，无法回滚时保留待恢复记录。已在目标位置的条目保留并在预览标题中计数；全部无需移动时不创建记录。

变量表格使用 Extended 选择，复选框可逐项勾选，表头可全选/取消当前筛选列表；也支持 Ctrl/Shift 多选和 Ctrl+A。刷新保留仍可见的选择，筛选移除隐藏条目的选择，切换页面/配置组时清除选择。右键已选行保留整组选中；多选时只允许移动，编辑/删除按钮禁用。批量对话框可保留各变量的原作用范围，或统一指定用户/系统范围。

本机环境提供“全部方式 / 本机值 / 配置组管理”及各已启用组的筛选，与用户/系统范围及变量搜索同时生效。归属依据所有启用组的已应用定义及变量范围、名称判断，外部改值不会改变管理归属；同一变量可属于多个组，表格显示叠加顺序。没有启用组时，管理筛选显示启用提示；切换到组定义页后隐藏并忽略本机应用方式筛选。表头全选只选择当前结果。

数据格式版本为 2。加载版本 1 时把 `Active` 迁移为一个启用组，并转换旧历史与待恢复记录；已写入值按设置/删除接续管理，保留原始恢复基准及尚未应用的编辑。下一次应用更新使用组定义中的操作方式。数据保存后旧版无法读取，升级前应备份整个 `data` 目录。序列化保留 `Profiles` 等字段名以兼容导入和旧数据。

0.2.1 的单实例按 Windows 会话、账号和数据目录区分。手动重复启动通过两个限当前账号访问的事件请求并确认显示现有窗口。登录任务的重复启动直接退出。可用 `.\test-reopen.ps1 -Executable .\build\SwitchEnv.exe` 在演示模式验证。

0.2.2 支持变量描述。本机描述按变量作用范围和名称存储在状态文件中，配置组描述存储在各组变量定义中。两个描述字段都是可选的，旧版数据可直接读取。移动、删除和撤销操作会在同一事务中保存相关描述。环境快照和已应用的组定义只记录实际的环境操作。
